Field notes

Scrollable

Scroll shadows are an old trick with a long JavaScript tail. For years the recipe was a scroll listener, some math against scrollHeight, and a pair of toggled classes. It worked, but it ran on the main thread and broke the moment content resized.

This version deletes all of that. The container publishes a scroll progress timeline, a native browser primitive that maps its own scroll position onto animation progress.

Two tiny keyframe animations ride that timeline. The top shadow fades in across the first bit of scrolling, so it only shows once something is actually hidden above you.

The bottom shadow plays the very same fade in reverse across the last stretch, so it disappears the moment there is nothing left below.

Because the browser owns the mapping, the shadows stay perfectly in sync while you drag, fling, or keyboard-scroll, and they keep working when content grows or shrinks.

No listeners to debounce, no observers to disconnect, nothing to keep alive. The whole effect is a stylesheet.

And it fails politely. Browsers without the feature simply show a plain scrolling panel, which is exactly what this would have been anyway.

Too short to scroll

No shadows

Same class, no shadows. This panel holds less content than its box, so there is no scrollable overflow.

Scroll-driven animations only activate when a container can actually scroll, and this part uses that as a detector: a no-op animation flips a custom property that switches the shadows on. Here it never runs, so the edges stay clean.

Delete a paragraph from a scroller and its shadows retire themselves.

How the trick works

Three small ideas stacked together, all native CSS.

1

Sticky gradients

The shadows are ::before and ::after strips pinned to the container edges with position: sticky, each painted as a soft radial gradient.

2

Scroll timeline fades

A named scroll-timeline on the container drives each strip's opacity, with animation-range pinning the fades to the first and last bit of scroll.

3

Can-scroll detection

Scroll-driven animations only run when there is overflow, so a no-op animation doubles as a detector and hides the shadows on panels that cannot scroll.
